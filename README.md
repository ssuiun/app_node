# SUKAAA — Railway + PostgreSQL

## Лист задач (marginalia.html)

`marginalia.html` теперь хранит список дел в PostgreSQL через API:

- `GET /api/storage?keys=marginalia_tasks_v2`
- `POST /api/storage`

Ключ `marginalia_tasks_v2` содержит JSON-массив задач.

При первом открытии «Листа задач»:
1. существующие задачи из PostgreSQL загружаются;
2. если остались старые задачи в localStorage — они один раз переносятся в PostgreSQL;
3. если данных нет — создаются стартовые задачи и сохраняются в PostgreSQL.

## Учёт виз («Визы и договоры» → вкладка «Визы»)

Визы хранятся в таблице `visa_records` PostgreSQL: **одна строка на визу**, общая для всех сотрудников.

- Записи разных сотрудников не затирают друг друга, даже если сохраняют одновременно (раньше весь список хранился одним значением и перезаписывался целиком).
- Страница сама обновляется раз в 5 секунд (и сразу при возвращении на вкладку), чужие визы появляются без F5. Если связи нет, над таблицей появится предупреждение.
- Вкладка «Отчёт» считает по этим же данным.
- Перенос старых записей автоматический: при первом запуске сервер переносит список из `app_storage` (старый ключ сохраняется как `vd_visas_backup`), а каждый браузер один раз отправляет на сервер свой локальный список (дубли по id пропускаются).
- API: `/api/visas` (GET, POST, PATCH/DELETE `/:id`, POST `/import`). Тест: `DATABASE_URL=postgres://... node --test test/visas.test.js`.

## Исходящие номера (`/outgoing.html`)

Реестр исходящих писем по компаниям в PostgreSQL (таблицы `out_companies`, `out_counters`, `out_letters`, `out_files` создаются автоматически при старте).

- **Компании** берутся из раздела «Визы и договоры» (карточки на вкладке «Компании»; переименование в визах подхватывается само). Клик по карточке — все письма компании. Можно добавить и компанию не из виз.
- У каждой компании своя нумерация. В настройках карточки (⚙): префикс (`ИСХ-`), номер, с которого продолжить (если уже вели нумерацию), сброс счётчика каждый год.
- «Получить номер» атомарно выдаёт следующий номер и записывает письмо (дата, адресат, тема, файлы). Одновременные запросы не дают одинаковых номеров. Для уже отправленных писем есть «Указать номер вручную» (занятый номер не принимается, следующие автономера идут после наибольшего).
- **Файлы** загружаются к письму и хранятся прямо в PostgreSQL. Через `OUT_FILE_RETENTION_DAYS` (по умолчанию 60 дней) они удаляются автоматически (проверка раз в 6 часов), письма в журнале остаются. За `OUT_FILE_WARN_DAYS` (14) дней на странице появляется напоминание с кнопками «Скачать эти файлы» и «Продлить срок». Лимит одного файла — `OUT_MAX_FILE_MB` (25).
- **Архив**: «Скачать всё архивом» (журнал в `Журнал.csv` + файлы по папкам «Компания / № письма»), архив одной компании и архив только «скоро удалятся».
- Номер и дату менять нельзя. Письмо можно удалить вместе с файлами (если это последний номер — он снова свободен) или аннулировать (останется в журнале, повторно не выдаётся).
- Журнал: поиск, фильтры по компании/году/статусу, выгрузка в Excel (CSV).
- Тест (нужен PostgreSQL): `DATABASE_URL=postgres://... npm run test:outgoing`.

## Клиенты (`/clients.html`)

База данных с двумя вкладками, в каждой — карточки:

- **Компании**: название, полное название, ИНН, ОКПО, директор, адрес, телефон, email, вид деятельности, регистрация, примечание.
- **Клиенты** (физические лица): ФИО, компания (выбирается из базы), должность, телефон, email, гражданство, паспорт, примечание.
- Поиск по всем полям, фильтр клиентов по компании («Без компании» тоже есть). Из карточки компании одним кликом открываются её клиенты, из карточки клиента — его компания.
- «Импорт из «Визы и договоры»» один раз добавляет компании из визового раздела (реквизиты подтягиваются). Повторный импорт ничего не дублирует и не затирает ваши правки.
- Удаление компании не удаляет её клиентов — они остаются без компании.
- **Файлы**: к каждой карточке (компании и клиента) можно приложить файлы — в окне карточки, при создании тоже. Хранятся прямо в PostgreSQL без срока, до `CL_MAX_FILE_MB` (по умолчанию 25) на файл. При удалении карточки её файлы удаляются.
- **Вид**: переключатель «▦ Карточки / ☰ Список» в правом верхнем углу; выбор запоминается в браузере и действует сразу во всех местах, где есть компании: «Клиенты», «Исходящие номера» → «Компании», «Визы и договоры» → «Компании».
- Таблицы `cl_companies`, `cl_clients`, `cl_files` создаются автоматически; API: `/api/clients/companies`, `/api/clients/clients`. Тест: `DATABASE_URL=postgres://... node --test test/clients.test.js`.

## Railway

1. Добавь в проект PostgreSQL через **New → Database → Add PostgreSQL**.
2. Подключи PostgreSQL к `SUKAAA`, чтобы сервис получил `DATABASE_URL`.
3. Сделай Redeploy.
4. Не задавай порт вручную: сервер использует `process.env.PORT`.

`/health` возвращает состояние приложения.

## PDF-инструменты (Stirling-PDF через `/pdf`)

Сайт проксирует путь `/pdf` на отдельный сервис Stirling-PDF (reverse proxy в `server.js`).

1. В том же проекте Railway: **New → Docker Image** → `stirlingtools/stirling-pdf:latest`
   (лучше закрепить конкретную версию).
2. Переменные сервиса Stirling-PDF:
   - `SYSTEM_ROOTURIPATH=/pdf`
   - `LANGS=ru_RU` (по желанию)
   - порт по умолчанию 8080; публичный домен для него создавать **не нужно**.
3. В сервисе сайта (`SUKAAA`) добавь переменную:
   - `STIRLING_URL=http://<имя-сервиса>.railway.internal:8080`
4. Redeploy обоих сервисов. Страница: `/#pdf` или `/pdf/`.

Если `STIRLING_URL` не задан, `/pdf` отключён.

### OCR на русском и кыргызском

В стандартном образе нет русского словаря Tesseract. Папка `stirling/` содержит Dockerfile,
который добавляет `rus` и `kir`. В Railway у сервиса `stirling-pdf`:
**Settings → Source** → подключить репозиторий `app_node`, **Root Directory** = `/stirling`.
Переменные сервиса (`PORT`, `SYSTEM_ROOTURIPATH`, `SYSTEM_DEFAULTLOCALE` и др.) сохраняются.

## Agentation (визуальные комментарии для ИИ)

Тулбар [Agentation](https://agentation.com): кликаете по элементу страницы, пишете замечание и копируете готовый текст для ИИ-агента (с селекторами элементов).
Включается переменной окружения `AGENTATION=1` (по умолчанию выключен; на Railway добавляйте только если нужен). Тулбар появляется справа внизу.
Пересборка бандла после обновления пакета: `npm run build:agentation` (результат — `public/vendor/agentation.js`, лежит в репозитории).

## Локальный запуск (localhost)

Нужны Node.js 20+ и Docker (для PostgreSQL).

```
git checkout claude/lucid-dirac-q2acjl
npm install
docker compose up -d        # база PostgreSQL на localhost:5432
cp .env.example .env        # настройки (DATABASE_URL, AGENTATION)
npm run dev
```

Сайт: http://localhost:3000 — раздел «Исходящие номера»: http://localhost:3000/#out
Без Docker можно указать в `.env` любую свою PostgreSQL-базу в `DATABASE_URL`.
